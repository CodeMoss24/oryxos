# 项目概述

OryxOS 是企业私有部署的 Agent 操作系统：**你用一句自然语言发布一个任务 → 底座把它拆解 → 组织一支 Agent 团队 → 多个 Agent 分工协作 → 交付一个结果。** 让每一家公司，都能用自然语言跑起来自己的 Agent。

## 为什么需要 OryxOS

每家公司都有该交给 Agent 的活，但 Agent 大多还停在 demo，卡在四道门槛上：

- **定义一个 Agent 要写代码**——最懂业务的人反而做不了
- **云平台要把数据拿走**——合规过不去
- **执行是黑盒**——没审计、没白名单、没人审批，企业不敢上生产
- **跑一个容易、跑一群难**——没有人把「一群 Agent 的操作系统」这一层交给你

OryxOS 一次拆掉这四道门槛：自然语言定义、私有部署、全链路审计加沙箱、以及为一整队 Agent 准备的生命周期与治理。

## Agent Harness OS

Agent runtime 是让单个 Agent 跑起来的执行内核。Agent Harness OS 在 runtime 之上，管理的是一群 Agent：多个 Agent 的生命周期、统一的对外渠道与对内接入、统一的记忆、多租户与治理，以及分布式形态下的跨节点协作。

**runtime 让一个 Agent 跑起来，Agent Harness OS 让一群 Agent 被运行和管理起来。** OryxOS 是后者。

## 五大核心能力

- **对接 LLM**：通过 Provider 抽象统一对接主流大模型，运行时切换无锁定
- **ReAct 循环**：自实现推理引擎，循环行为完全可控
- **记忆**：会话记忆加长期记忆两层，接口预留向量检索升级空间
- **工具体系**：内置基础工具 + 三档扩展接入（零代码 / 轻代码 / 重代码）
- **对外服务**：REST API 对外暴露，任何语言可集成

## 核心特性

- 🤖 **一个目录 = 一个 Agent**：一个 `AGENT.md` 定义一个 Agent，不用写代码
- ☕ **Java 原生**：JDK 21，单 JAR 部署，复用 Java 运维工具链
- 🔒 **私有可控**：装在企业自己的服务器上，数据不出域
- 🛡️ **安全隔离**：白名单校验 + 强制沙箱 + 全链路审计
- 🧠 **自实现 ReAct**：核心循环自己实现，不套外部框架
- 🔌 **对接开放标准**：工具用 MCP、Agent 协作用 A2A
- 🧩 **三档工具扩展**：零代码 → 轻代码 → 重代码，按门槛自由选择
- 💾 **跨对话记忆**：会话 + 长期两层记忆
- 🌐 **无状态可扩展**：状态外置，为走向分布式留好路

## 设计原则

- **底座优先于 Agent**：最重要的交付是让任意 Agent 都能可靠运行的环境
- **配置即 Agent**：一个 Agent 由一份配置定义，而不是由代码写出
- **对接开放标准**：工具用 MCP、协作用 A2A，与生态协同
- **安全是地基不是补丁**：安全从第一天就在架构里
- **分阶段克制**：每次架构升级都用真实使用数据证明其必要性
